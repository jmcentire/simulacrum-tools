Simulacrum

A cognitive simulacrum of Jeremy McEntire.

A simulacrum is a model of someone's cognitive moves — the specific patterns of thought they apply to novel situations. It is NOT a style-transfer of their writing voice. The two get conflated; they are not the same problem.
Try it live → Source on GitHub

What it is

An open-source generative agent system that mimics how one specific person reasons — not how they write. It engages with arguments the way Jeremy does: interrogates load-bearing assumptions, demands operationalized criteria, refuses well-shaped questions only when the shape is genuinely malformed, demolishes the framing when it isn't.

Built on the two-phase classifier-dispatch architecture from Park et al.'s 2024 paper, Generative Agent Simulations of 1,000 People, with a recall-vs-content split that routes each turn to the agent best suited to it.

How it works

  1. Classifier — a fast Anthropic Sonnet call labels each turn as GENERALIST (autobiographical recall) or SPECIALIST (opinion, drafting, critique, adversarial framing, multi-turn dialog).
  2. Dispatch:
    • GENERALIST → OpenAI fine-tune on Jeremy's prior writing (optional; recall accelerator).
    • SPECIALIST → Anthropic Sonnet + 11 hand-annotated few-shot pairs + a Mode-A operationalized-criterion sub-classifier.

The system prompt carries two load-bearing meta-rules: assumption-interrogation (before applying conventional advice, identify the assumption it depends on and check whether it holds) and architecture-review posture (when reviewing existing systems, identify the constraint envelope first; demand it if missing; don't alternative-shop).

Build your own

The repo is configured as Jeremy's simulacrum, but the pattern transfers. See PRIMER.md for a step-by-step recipe distilled from eight architectural iterations: what works (annotated few-shot, two-phase dispatch), what doesn't (graph retrieval, multi-substrate ensembles, behavior dispatchers), and the order of operations that avoids the dead ends.

Quick start (local CLI)

git clone https://github.com/jmcentire/simulacrum-tools.git
cd simulacrum/skill
ln -s ../fly/data/adversarial_pairs_annotated.json .
pip install anthropic openai
export WANDER_ANTHROPIC_API_KEY=sk-ant-...  # preferred when available
# Portable fallback: export ANTHROPIC_API_KEY=sk-ant-...
./run.py "Every team needs a strong manager."

Quick start (Claude Code plugin)

git clone https://github.com/jmcentire/simulacrum-tools.git
claude --plugin-dir ./simulacrum

Invoke /simulacrum:get-advice with an idea, plan, claim, draft, or architecture question.

Quick start (Fly deployment)

cd simulacrum/fly
fly launch --no-deploy --copy-config       # rename the app
fly secrets set WANDER_ANTHROPIC_API_KEY="$WANDER_ANTHROPIC_API_KEY"
fly secrets set SIMULACRUM_TOKEN=$(openssl rand -hex 32)
fly deploy

Anti-abuse posture

The deployment is open (no login). Defenses are layered:

  1. Cookie-based 20-message rolling 24h cap — HMAC-signed, no server state.
  2. Cloudflare Turnstile invisible bot-check (optional; activated when TURNSTILE_SECRET is set).
  3. Cloudflare edge in front: Bot Fight Mode, per-IP rate limiting.
  4. Provider-side daily budget cap on your API key.
